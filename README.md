# toxicity-comments-russian

## Постановка задачи

Задача состоит в классификации комментариев на русском языке на токсичные / нетоксичные.

Полезность заключается в возможности модерации комментариев, тем самым повышая пользовательский опыт платформы ok.ru.

### Формат входных и выходных данных

Входные метрики: текст, не более 512 токенов.

Выходные: 1 - если комментарий токсичный, 0 - если комментарий не токсичный.

### Метрики

В данной задаче из-за дисбаланса классов (токсичных << нетоксичных) будем опираться на F1-score, Recall и Precision (эти метрики естественным образом зависят от трешхолда), поэтому как основную метрику будем рассматривать ROC-AUC (>= 0.8) (https://github.com/unitaryai/detoxify - здесь получается 0.89, но сделаем поправку на русский язык)

### Валидация и тест

Будем использовать разделение на train/val/test (т.к. данных довольно много). На train/test датасет делится автоматически (см. карточку HF)/ Для валидации используем разделение исходного train на train/val, отношение валидации - 0.1, при помощи stratified split с фиксированным random_seed=42.

### Датасеты

Датасет (https://huggingface.co/datasets/AlexSham/Toxic_Russian_Comments) - формата текст-метка.
Этот датасет содержит помеченные комментарии из популярной российской социальной сети ok.ru.

Данные были использованы в конкурсе, в котором участники должны были автоматически пометить каждый комментарий как минимум одним из четырёх предопределённых классов. Классы представляют разные уровни токсичности. Конкурс проводился на платформе All Cups. Однако, здесь мы берем классы только токсичен (в любой категории) или не токсичные.
Для train - 223k сэмплов, причем, вероятно, придется отсекать длинные комментарии (останется 80%) (или делать truncation просто).

## Моделирование

### Бейзлайн

Как бейзлайн возьму tf-idf + logreg.

### Основная модель

Как backbone возьмем ruRoberta-large (cointegrated/rubert-tiny2) на задачу классификации.

### Внедрение

Модель будет использоваться в виде REST API-сервиса, который принимает текст комментария и возвращает логиты.

## Setup

- Создаййте новое виртуальное окружение при помощи uv и установите зависимости.

```
uv sync
```

## Train
- Активируйте окружение

- Скачайте данные с HF, запустите MLFlow и начните обучение

```
python3 toxicity_comments_russian/download_data.py
./start_mlflow_server.sh
python3 toxicity_comments_russian/train.py
```

## Model production packaging

- Если не было этапа Train, то необходимо загрузить модел с HF.

```
python3 toxicity_comments_russian/download_model.py.py
```

- Для того, чтобы перевести модель в ONNX формат и зарегестрировать в MLFlow

```
python3 toxicity_comments_russian/model_to_onnx.py
python3 toxicity_comments_russian/mlflow_server.py
```

## Infer

Необходимо запустить сервер

```
mlflow models serve -m "models:/toxic_russian_comments_onnx/<version>" -p 5000 --no-conda
```

`<version>` - смотри в выводе команды mlflow_server.py

Для примера смотри examples.py
